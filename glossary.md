# Glossary

Short definitions of terms used across this knowledge base. Each entry links
to the topic that explains it in depth; read that file before applying the idea.
Not a topic file: `build_index.py` skips it for INDEX.md but checks its `[[links]]`.

- **3-2-1 backup rule** - keep 3 copies of data, on 2 different media types, with 1 copy offsite. [[backup-and-disaster-recovery]]
- **ABAC (attribute-based access control)** - access decided by rules over attributes of the user, resource and context rather than fixed roles. [[authorization-models]]
- **Active-active / active-passive** - every region serves traffic, versus one region serving while standbys receive replicated data and take over on failover. [[multi-region-architecture]]
- **Adaptive bitrate streaming (HLS/DASH)** - video cut into short segments at several bitrates so the player can switch quality as bandwidth changes. [[design-video-streaming]]
- **ADR (architecture decision record)** - a short, dated document recording one significant decision, its context and its consequences. [[architecture-decision-records]]
- **Aggregate** - a cluster of domain objects changed together through one root that enforces its invariants; the unit of a transaction in DDD. [[domain-driven-design]]
- **Amortized cost** - the average cost per operation over a worst-case sequence, e.g. appends to a dynamic array that occasionally resizes. [[big-o-complexity]]
- **Approximate nearest neighbour (ANN)** - a vector index (HNSW, IVF) that finds most of the k closest vectors much faster than exact search, trading recall for latency. [[vector-databases-for-engineers]]
- **Async request-reply** - an API returns 202 Accepted with a status resource the client polls (or is called back about) until slow work finishes. [[long-running-operations]]
- **At-least-once delivery** - every message is delivered one or more times; duplicates are possible, so consumers must be idempotent. [[idempotency-and-exactly-once]]
- **Backpressure** - a slow consumer signalling producers to slow down (or rejecting work) instead of buffering without limit. [[message-queues-and-streams]]
- **Base62 encoding** - writing a number with the characters 0-9, a-z and A-Z to make short, URL-safe codes. [[design-url-shortener]]
- **Baseline (static analysis)** - a recorded set of existing findings so a new check fails only on new ones; the baseline is then shrunk over time (ratcheting). [[static-analysis-and-type-checking]]
- **Blameless postmortem** - an incident review that looks for the system and process causes of a failure rather than a person to blame. [[incident-response-and-postmortems]]
- **Blast radius** - how many users, requests or hosts a change or a fault-injection experiment can affect; kept small and widened only after it proves safe. [[chaos-engineering]]
- **Bloom filter** - a compact probabilistic set that answers "definitely not present" or "maybe present"; no false negatives, tunable false positives. [[probabilistic-data-structures]]
- **Blue-green deployment** - run the new version beside the old one and switch all traffic at once, keeping the old one for instant rollback. [[deployment-strategies]]
- **Bounded context** - a part of the domain with its own model and language; the natural boundary for a service or module. [[domain-driven-design]]
- **Breaking change** - an API change that makes existing, correct clients fail, such as removing a field or tightening validation. [[api-versioning-and-evolution]]
- **Bulkhead** - isolating resources (pools, queues) per dependency so one failing dependency cannot exhaust them all. [[resilience-patterns]]
- **Cache-aside** - the application reads the cache, falls back to the database on a miss and fills the cache itself. [[caching-strategies]]
- **Cache busting** - putting a content hash in an asset URL so it can be cached long-term and every deploy gets a new URL. [[web-performance]]
- **Cache stampede (thundering herd)** - many requests miss the same expired key at once and all hit the backing store. [[caching-strategies]]
- **CalVer (calendar versioning)** - version numbers taken from the release date, such as `2026.10.1`. [[release-versioning-and-changelogs]]
- **Canary release** - send a small share of traffic to the new version and widen it only while its metrics stay healthy. [[deployment-strategies]]
- **CAP / PACELC** - under a network partition choose consistency or availability; else trade latency against consistency. [[cap-and-pacelc]]
- **Cell-based architecture** - many isolated copies of the full stack, each serving a slice of customers behind a thin router, so one failure or bad deploy affects one cell only. [[multi-region-architecture]]
- **Change data capture (CDC)** - turning a database's committed inserts, updates and deletes, usually read from its replication log, into an ordered stream for other systems. [[change-data-capture]]
- **Chaos engineering** - controlled experiments that inject real faults to test a hypothesis that the system's steady state holds. [[chaos-engineering]]
- **Circuit breaker** - stop calling a failing dependency for a while after repeated errors, then probe before resuming. [[resilience-patterns]]
- **Code smell** - a surface pattern (long method, feature envy, duplicated logic) that hints at a deeper design problem worth refactoring. [[refactoring-and-code-smells]]
- **Cold start** - the extra latency when a serverless platform has to start a new instance before it can handle a request. [[serverless-architecture]]
- **Compaction (LSM)** - background merge of an LSM-tree's sorted runs that drops overwritten values and tombstones; leveled favours space and reads, size-tiered favours writes. [[storage-engines-btree-lsm]]
- **Composition root** - the one place near the program's entry point where all dependencies are constructed and wired together. [[dependency-injection]]
- **Cone of uncertainty** - early estimates are inherently wide and narrow only as decisions are made and work is done. [[estimation-and-planning]]
- **Configuration drift** - live infrastructure diverging from what its code declares, usually after manual changes. [[infrastructure-as-code]]
- **Connection pool** - a bounded set of open database connections lent to requests, removing per-request handshakes and capping concurrency on the database. [[database-connection-pooling]]
- **Consistent hashing** - placing keys and nodes on a ring so adding or removing a node moves only a small share of keys. [[consistent-hashing]]
- **Consumer group** - a set of consumers that share a stream's partitions, each partition read by one member. [[message-queues-and-streams]]
- **Container image** - an immutable, layered package of an application and its filesystem dependencies, from which containers are started. [[containers-and-docker]]
- **Content Security Policy (CSP)** - a response header restricting where a page may load scripts, styles and frames from; a strict, nonce-based CSP limits the damage of XSS. [[browser-security-cors-csp-headers]]
- **Content-addressed storage** - storing each block under the hash of its contents, so identical blocks are stored once and integrity is checkable. [[design-file-sync]]
- **Continuous delivery / continuous deployment** - every change that passes the pipeline is releasable (delivery) or is released automatically (deployment). [[ci-cd-pipelines]]
- **Contract test** - a test that checks a provider still honours the requests and responses its consumers rely on. [[integration-and-contract-testing]]
- **Conventional Commits** - a commit message format (`feat:`, `fix:`, `!` for breaking) that tools use to compute the next version and changelog. [[release-versioning-and-changelogs]]
- **Core Web Vitals** - Google's three page-experience metrics (LCP, INP, CLS), judged at the 75th percentile of real page loads. [[browser-rendering-and-core-web-vitals]]
- **CORS (cross-origin resource sharing)** - response headers by which a server lets script from other origins read its responses; it relaxes the same-origin policy and does not stop requests being sent. [[browser-security-cors-csp-headers]]
- **Count-Min Sketch** - a matrix of counters that estimates item frequencies in a stream in fixed memory; it can overestimate but never underestimates. [[probabilistic-data-structures]]
- **Covering index** - an index that contains every column a query needs, so the query never reads the table. [[database-indexing]]
- **CQRS** - separating the write model (commands) from one or more read models (queries). [[cqrs-and-event-sourcing]]
- **CRDT** - a conflict-free replicated data type: replicas apply edits in any order and still converge to the same state. [[design-collaborative-editor]]
- **Crypto-shredding** - erasing data by deleting the per-subject encryption key, which leaves every copy unreadable. [[privacy-and-pii-handling]]
- **CSRF** - a malicious site making the victim's browser send an authenticated request with its cookies. [[authentication-and-sessions]]
- **Cuckoo filter** - a fingerprint-based alternative to a Bloom filter that also supports deletion. [[probabilistic-data-structures]]
- **DataLoader** - a per-request batching and caching layer that collects the keys GraphQL resolvers ask for and loads them in one batched query, avoiding N+1. [[graphql]]
- **Dead-letter queue** - where messages go after repeated processing failures, so they stop blocking the queue and can be inspected. [[message-queues-and-streams]]
- **Decision guide (chooser)** - a scenarios/ file that maps a concrete problem or requirement to a recommended approach and the topic files to read next. [[scenario-chooser]]
- **Delta-of-delta encoding** - storing the change between consecutive timestamp deltas, so regular intervals compress to about one bit per sample (Gorilla). [[time-series-databases]]
- **Denormalization** - deliberately duplicating data across tables or documents to make reads cheaper at the cost of harder writes. [[data-modeling-and-schema-design]]
- **Device token (push token)** - the identifier APNs or FCM issues for one app install; it is registered with the backend, refreshed when it changes and pruned when the provider reports it invalid. [[design-notification-system]]
- **Diataxis** - a documentation framework with four kinds of docs: tutorials, how-to guides, reference and explanation. [[documentation-practices]]
- **Distributed tracing** - following one request across services with a shared trace ID and timed spans. [[observability-logs-metrics-traces]]
- **Double-entry ledger** - every money movement recorded as balanced debit and credit entries, so the books always sum to zero. [[design-payment-system]]
- **Envelope encryption** - encrypting data with a data key and encrypting that key with a master key held in a KMS. [[secrets-management]]
- **Error budget** - the unreliability an SLO allows (100% minus the target), spent on releases and risk. [[slis-slos-error-budgets]]
- **Event-carried state transfer** - events that carry the full changed state, so consumers keep a local copy instead of calling back. [[event-driven-architecture]]
- **Event loop** - one thread that waits on many non-blocking I/O sources and runs the handler for whichever is ready. [[processes-threads-and-io-models]]
- **Event sourcing** - storing the sequence of state-changing events as the source of truth and deriving current state from it. [[cqrs-and-event-sourcing]]
- **Eventual consistency** - replicas may disagree for a while but converge once updates stop. [[consistency-models]]
- **Expand/contract migration** - add the new schema alongside the old, move code and data over, then remove the old, so every step is backward compatible. [[schema-migrations]]
- **Exponential backoff with jitter** - retry delays that grow each attempt and are randomised so clients do not retry in lockstep. [[resilience-patterns]]
- **Fail open / fail closed** - when a check such as a rate limiter cannot decide, either allow the request (open) or reject it (closed). [[design-rate-limiter]]
- **False sharing** - threads writing different variables on the same cache line, so the line bounces between cores. [[cpu-caches-and-memory-hierarchy]]
- **Fan-out on write / on read** - push a new item to every follower's feed when posted, or assemble the feed when it is read. [[design-news-feed]]
- **Feature flag** - a runtime switch that turns code paths on or off without a deploy. [[feature-flags]]
- **Fencing token** - a number that increases with every lock grant; the protected resource rejects writes carrying a lower token than one it has already seen, so a paused former lock holder or old leader cannot overwrite newer data. [[distributed-locks-and-leader-election]]
- **Finite state machine** - a model with a fixed set of states and allowed transitions, so illegal state changes are impossible by construction. [[state-machines]]
- **Flaky test** - a test that passes and fails on the same code, usually from timing, ordering or shared state. [[flaky-tests]]
- **Functional core, imperative shell** - pure decision logic in the middle, with I/O kept in a thin outer layer that calls it. [[functional-core-imperative-shell]]
- **Functional vs non-functional requirements** - what the system must do (features) versus how well it must do it (latency, availability, scale, cost); clarify both before drawing boxes. [[system-design-interview-framework]]
- **Game day** - a scheduled session where a team triggers failures on purpose to test the system, alerts and runbooks. [[chaos-engineering]]
- **Geohash** - encoding a latitude/longitude as a string whose shared prefixes mean nearby cells, for proximity lookups. [[design-ride-sharing]]
- **Golden file (snapshot) test** - comparing output against a stored, reviewed copy and failing on any difference. [[snapshot-and-golden-testing]]
- **Gossip protocol** - nodes periodically exchange state with a few random peers, so information reaches the whole cluster in about log(n) rounds without a coordinator. [[gossip-and-failure-detection]]
- **Graceful shutdown** - on SIGTERM, fail readiness, keep serving while load balancers notice, finish in-flight work up to a deadline, then exit. [[health-checks-and-graceful-shutdown]]
- **Gradual typing** - optional type annotations; unannotated code is treated as `Any`, so a type checker's strictness can be raised module by module (PEP 484). [[static-analysis-and-type-checking]]
- **Grapheme cluster** - what a user sees as one character, which may be several Unicode code points (an emoji with modifiers, a letter with accents). [[strings-and-text-encoding]]
- **Head-of-line blocking** - one lost or slow item stalling everything queued behind it, as one lost packet does to a TCP stream. [[networking-fundamentals]]
- **Heap (priority queue)** - a tree kept in an array where the smallest (or largest) item is always at the root: O(1) peek, O(log n) push and pop; the basis of top-k and scheduling. [[core-data-structures]]
- **Hexagonal architecture (ports and adapters)** - domain logic in the centre talking to the outside world only through interfaces. [[layered-hexagonal-clean-architecture]]
- **High cardinality** - a metric label with very many distinct values (user IDs, URLs), which multiplies the number of stored series. [[design-metrics-logging-pipeline]]
- **Hinted handoff** - a node temporarily accepts writes for an unreachable replica and forwards them when it returns. [[design-key-value-store]]
- **HMAC signature** - a keyed hash proving a message came from a holder of the shared secret and was not altered. [[webhooks]]
- **Home region** - the one region that owns writes for a user, tenant or entity in an active-active deployment, avoiding cross-region write conflicts. [[multi-region-architecture]]
- **Horizontal vs vertical scaling** - adding more machines versus giving one machine more CPU, memory or disk. [[capacity-planning-and-autoscaling]]
- **HSTS** - the Strict-Transport-Security header, telling browsers to use only HTTPS for a host for a set time, defeating SSL-stripping downgrades. [[browser-security-cors-csp-headers]]
- **HttpOnly cookie** - a cookie flag that hides the cookie from JavaScript, so an XSS bug cannot read the session ID; the default carrier for first-party web sessions with `Secure` and `SameSite`. [[choosing-an-auth-approach]]
- **HyperLogLog** - a sketch that estimates the number of distinct items with a few kilobytes of registers and a relative error of about 1.04/sqrt(registers); sketches merge by register-wise max. [[probabilistic-data-structures]]
- **Idempotency key** - a client-generated ID sent with a request so the server can return the stored result on a retry instead of repeating it. [[idempotency-and-exactly-once]]
- **Idempotent and safe HTTP methods** - safe methods (GET, HEAD) change nothing; idempotent ones (also PUT, DELETE) have the same effect when repeated. [[rest-api-design]]
- **Index-free adjacency** - native graph storage where each node points directly at its relationships, so following an edge needs no index lookup. [[graph-databases]]
- **Intention-revealing name** - a name that says why a thing exists and how it is used, so the reader needs no comment to understand it. [[clean-code-and-naming]]
- **Inverted index** - a map from each term to the documents that contain it; the core structure of full-text search. [[search-systems]]
- **Isolation level** - how much concurrent transactions may see of each other (read committed, repeatable read, serializable). [[transactions-and-isolation-levels]]
- **JWT** - a signed, self-contained token carrying claims; verifiable without a database lookup but hard to revoke early. [[authentication-and-sessions]]
- **Keyset (cursor) pagination** - paging by "rows after this sort key" instead of an offset, so pages stay fast and stable. [[pagination-filtering-sorting]]
- **Kill switch** - an ops feature flag that turns a feature or dependency off at runtime without a deploy. [[feature-flags]]
- **L4 / L7 load balancing** - balancing on TCP/UDP connections only (layer 4) or on HTTP requests, paths and headers (layer 7). [[load-balancing]]
- **Lamport / vector clock** - logical clocks that order events without trusting wall-clock time. [[time-clocks-and-ordering]]
- **Law of Demeter** - talk only to immediate collaborators, not to the internals of objects they return. [[coupling-cohesion-and-design-principles]]
- **Leader election** - nodes agreeing on a single leader, normally through a consensus protocol. [[consensus-raft-paxos]]
- **Lease** - a lock or leadership grant that expires unless renewed, so a crashed holder cannot block others forever. [[distributed-locks-and-leader-election]]
- **Linearizability** - every operation appears to take effect atomically at one point between its start and end; the strongest single-object guarantee. [[consistency-models]]
- **Liskov substitution principle** - a subtype must work wherever its base type is expected, without callers noticing. [[solid-principles]]
- **Little's Law** - average items in a system = arrival rate x average time each spends there; used to size pools, workers and queues. [[database-connection-pooling]]
- **Liveness probe** - a health check whose failure restarts the instance; it should test only the process, never shared dependencies. [[health-checks-and-graceful-shutdown]]
- **Long polling** - the client sends a request that the server holds open until there is new data or a timeout, then the client asks again. [[choosing-realtime-updates]]
- **Modular monolith** - one deployable unit split into modules with enforced boundaries, often a step before or instead of microservices. [[monolith-vs-microservices]]
- **Module boundary check** - a CI lint (import-linter, packwerk, ArchUnit) that fails on imports into another module's internals or on cycles between modules. [[modular-monolith]]
- **mTLS** - TLS where both client and server present certificates, authenticating service to service. [[cryptography-and-tls]]
- **Mutation score** - the share of deliberately injected code changes (mutants) that the test suite detects. [[mutation-testing]]
- **MVCC** - multi-version concurrency control: readers see a snapshot while writers create new row versions. [[transactions-and-isolation-levels]]
- **N+1 queries** - one query for a list followed by one query per item, usually hidden behind an ORM. [[orm-and-n-plus-one]]
- **Nit (code review)** - a review comment labelled optional, such as a style preference, that the author may take or leave without blocking the merge. [[code-review]]
- **Noisy neighbour** - one tenant's load degrading the others in a shared (pooled) system. [[choosing-a-multi-tenancy-model]]
- **NoSQL** - an umbrella for key-value, document, wide-column and graph stores that trade joins, fixed schema or multi-row transactions for scale, flexible schema or a specialised access pattern. [[sql-vs-nosql]]
- **Object storage** - a flat store of immutable blobs addressed by key (S3, GCS, Azure Blob) with metadata kept in your database; the default home for uploaded files and media. [[choosing-file-and-media-storage]]
- **OLAP / star schema** - analytical queries over a fact table joined to dimension tables. [[data-warehousing-and-olap]]
- **Origin shield** - a middle cache tier that collapses misses from many CDN edge locations into one request to the origin. [[cdn-and-edge]]
- **Outbox pattern** - write the event to an outbox table in the same transaction as the state change, then publish it from there. [[distributed-transactions-and-sagas]]
- **p99 latency** - the latency 99% of requests stay under; tail latency that averages hide. [[performance-and-load-testing]]
- **Phi accrual failure detector** - outputs a suspicion level from the history of heartbeat inter-arrival times instead of a fixed timeout; the application picks the threshold. [[gossip-and-failure-detection]]
- **PKCE** - a per-login code verifier that stops a stolen OAuth authorization code from being redeemed. [[oauth2-and-oidc]]
- **Polyglot persistence** - using several kinds of datastore in one system, each for the access pattern it suits. [[choosing-a-database]]
- **Presence** - showing which users are online or typing, kept fresh by heartbeats over persistent connections. [[design-chat-system]]
- **Presigned URL** - a time-limited URL signed by the server that lets a client upload or download one object directly from object storage. [[blob-object-storage]]
- **Profiling** - measuring where a program actually spends time or memory before optimising it. [[memory-and-performance]]
- **Property-based testing** - generating many inputs and checking properties that must hold for all of them. [[property-based-and-fuzz-testing]]
- **Protobuf field number** - the number that identifies a field on the wire; it must never be reused or changed once clients exist. [[grpc-and-protobuf]]
- **Pseudo-localization** - automated fake translation (accents, padding, delimiters) that exposes hard-coded strings and truncation before real translation. [[internationalization-and-localization]]
- **Pseudonymisation** - processing personal data so it cannot be tied to a person without separately held extra information; it is still personal data. [[privacy-and-pii-handling]]
- **QPS (queries per second)** - request rate, estimated as daily requests / 86,400 and multiplied by a peak factor; the first number in a back-of-envelope sizing. [[back-of-envelope-estimation]]
- **Quorum** - the number of replicas that must acknowledge a read or write (R + W > N for overlapping reads and writes). [[replication]]
- **Race condition** - a result that depends on the timing of concurrent operations on shared state. [[concurrency-and-parallelism]]
- **RAG (retrieval-augmented generation)** - retrieving relevant documents and passing them to an LLM so its answer is grounded in them, with citations. [[design-rag-chat]]
- **RBAC** - access granted through roles assigned to users. [[authorization-models]]
- **Readiness probe** - a Kubernetes check that decides whether a pod receives traffic, separate from the liveness check that restarts it. [[kubernetes-basics]]
- **Read repair** - fixing a stale replica when a read notices it disagrees with others. [[replication]]
- **Read replica** - a copy of the database that serves reads, taking load off the primary at the cost of replication lag. [[scaling-from-zero-to-millions]]
- **Red-green-refactor** - the TDD loop: write a failing test, make it pass simply, then clean up with the test as a safety net. [[tdd-and-bdd]]
- **Replication slot** - Postgres server-side state that tracks how far a replication or CDC consumer has read and retains WAL until it confirms. [[change-data-capture]]
- **Result type** - returning success or a typed error as a value instead of raising, so callers must handle both. [[error-handling-strategies]]
- **robots.txt and politeness** - a site's crawl rules, plus per-host rate limits a crawler applies so it never overloads one site. [[design-web-crawler]]
- **RPO / RTO** - recovery point objective (maximum acceptable data loss, measured as time) and recovery time objective (maximum acceptable downtime). [[backup-and-disaster-recovery]]
- **Saga** - a long-running transaction split into local steps, each with a compensating action to undo it. [[distributed-transactions-and-sagas]]
- **Same-origin policy** - the browser rule that script from one origin (scheme, host, port) cannot read responses or DOM from another. [[browser-security-cors-csp-headers]]
- **SAST (static application security testing)** - static analysis that looks for vulnerabilities, often by tracking untrusted data from sources to dangerous sinks (taint analysis). [[static-analysis-and-type-checking]]
- **SBOM** - software bill of materials: a machine-readable list of the components and versions in an artifact (SPDX, CycloneDX). [[software-supply-chain-security]]
- **Seat hold** - a temporary, expiring reservation of specific inventory while the buyer pays. [[design-ticket-booking]]
- **Semantic versioning** - MAJOR.MINOR.PATCH, where only a major bump may break callers. [[library-api-design]]
- **Server-Sent Events (SSE)** - a one-way stream of text events from server to browser over a long-lived HTTP response. [[realtime-websockets-sse]]
- **Service mesh (sidecar)** - a proxy beside every service instance that handles mTLS, retries and telemetry outside the application code. [[api-gateway-and-service-mesh]]
- **Sharding (partitioning)** - splitting data across nodes by a key so each node holds a subset. [[partitioning-and-sharding]]
- **SKIP LOCKED** - `SELECT ... FOR UPDATE SKIP LOCKED` in Postgres and MySQL: each worker claims due rows that no other transaction has locked, so many workers poll one jobs table without blocking each other. [[design-job-scheduler]]
- **Sliding window (technique)** - keeping a moving range over a sequence and updating it incrementally instead of recomputing it. [[algorithm-patterns]]
- **SLI / SLO** - a measured indicator of service health and the target it must meet. [[slis-slos-error-budgets]]
- **SLSA** - Supply-chain Levels for Software Artifacts: levels for build integrity and provenance. [[software-supply-chain-security]]
- **Snowflake ID** - a 64-bit ID packing a timestamp, a machine ID and a sequence number, unique without coordination and roughly time-ordered. [[unique-id-generation]]
- **Split brain** - two nodes both believing they are leader after a partition, accepting conflicting writes. [[failure-modes-and-fallacies]]
- **SSRF** - server-side request forgery: tricking a server into fetching a URL of the attacker's choice, often an internal one. [[owasp-top-10]]
- **Stale-while-revalidate** - serve a cached response after it expires while refreshing it in the background. [[choosing-a-caching-strategy]]
- **Static stability** - a system keeps working through a failure without needing to change anything, for example by already running spare capacity in surviving zones or regions. [[multi-region-architecture]]
- **Steady-state hypothesis** - the prediction a chaos experiment tests: a user-facing metric stays in its normal range while a fault is injected. [[chaos-engineering]]
- **Strangler fig** - replacing a legacy system piece by piece by routing more and more traffic to the new one. [[migrating-monolith-to-services]]
- **Strategy pattern** - interchangeable algorithms behind one interface, chosen at runtime. [[design-patterns-gof]]
- **STRIDE** - a threat checklist: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege. [[threat-modeling]]
- **SWIM** - a membership protocol that probes one random member per period, uses indirect probes through peers before suspecting it, and piggybacks membership changes on probes. [[gossip-and-failure-detection]]
- **Synchronous vs asynchronous communication** - the caller waits for the answer (request/response: REST, gRPC) versus hands work off and moves on (queues, events), trading immediacy for decoupling and buffering. [[choosing-communication-style]]
- **Technical debt** - the future cost of a shortcut taken now, paid as slower change until it is fixed. [[technical-debt-management]]
- **Test data builder** - a helper that creates valid test objects with defaults, so each test states only what it cares about. [[test-data-management]]
- **Test double** - a stand-in for a real dependency in a test: stub, fake, mock, spy or dummy. [[unit-testing-and-test-doubles]]
- **Testing pyramid** - many fast unit tests, fewer integration tests and few end-to-end tests. [[testing-strategy-and-pyramid]]
- **Token bucket** - a rate limiter where tokens refill at a fixed rate and each request spends one, allowing short bursts. [[rate-limiting]]
- **Topological sort** - ordering a directed acyclic graph so every node comes before the nodes that depend on it. [[graph-algorithms]]
- **Transaction pooling** - an external pooler (such as PgBouncer) mode that returns the server connection after each transaction, multiplexing many clients but breaking session state. [[database-connection-pooling]]
- **Trie** - a prefix tree where each path from the root spells a prefix, used for autocomplete. [[design-search-autocomplete]]
- **Trunk-based development** - everyone merges small changes to one main branch at least daily, hiding unfinished work behind flags. [[git-workflows-and-branching]]
- **Twelve-factor app** - a methodology for portable, horizontally scalable services: config in the environment, stateless processes, backing services as attached resources. [[twelve-factor-app]]
- **Two-phase commit (2PC)** - a coordinator asks all participants to prepare, then tells them all to commit or abort. [[distributed-transactions-and-sagas]]
- **Virtual nodes** - many ring positions per physical node in consistent hashing, to even out load. [[consistent-hashing]]
- **Visibility timeout** - how long a claimed message stays hidden from other workers; if not acknowledged in time it is redelivered. [[background-jobs-and-queues]]
- **Watermark (stream processing)** - an estimate that no events older than a given time are still to come, used to close windows. [[batch-and-stream-processing]]
- **WCAG** - W3C Web Content Accessibility Guidelines: testable success criteria at levels A, AA and AAA under four principles (POUR). [[accessibility-basics]]
- **WIP limit** - a cap on how many items may be in one workflow stage at once, so work finishes before more starts. [[agile-scrum-kanban]]
- **Write-ahead log (WAL)** - an append-only log of changes made durable before the data pages, so committed work survives a crash by replaying it. [[storage-engines-btree-lsm]]
- **Write amplification** - bytes the storage engine writes to disk per byte the application writes, driven mainly by compaction or page rewrites. [[storage-engines-btree-lsm]]
